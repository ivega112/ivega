These files use a custom prototyping runtime (`<x-dc>`, `<sc-if>`, `<sc-for>`, `<dc-import>`) and are a **visual/interaction spec only** — not code to port literally.

## Notes on file→route consolidation

Several prototype files use a single component with a `mode`/`screen` prop to cover multiple production routes (a pattern worth preserving in Next.js via shared layout + route-level data fetching, not necessarily a single client component):
- `PageShop.dc.html` → 4 routes (`/shop`, `/category/[slug]`, `/offers`, `/search`)
- `PageBrands.dc.html` → 2 routes (`/brands`, `/brand/[slug]`)
- `PageCart.dc.html` → 3 routes (`/wishlist`, `/cart`, `/cart/review`)
- `AdminProducts.dc.html` → 2 routes; `AdminTaxonomy.dc.html` → 2 routes; `AdminHomepage.dc.html` → 2 routes (+3 sub-tabs); `AdminSettings.dc.html` → 8 routes

`PageDocs.dc.html` and `PageSupport.dc.html` both contain FAQ accordions but with different capabilities (categorized-with-chips vs plain) — production should converge these into one `FAQAccordion` component with an optional `categories` prop rather than maintaining two implementations.
